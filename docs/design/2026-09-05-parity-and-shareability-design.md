# 拾光 · 补齐与"可安全分享"设计方案

日期：2026-09-05
状态：待评审

## 一、这份文档要解决什么

对照 GitHub 上的同类产品（hindcast、codex-trace、CCHV、zoetrope、sessions-viewer、agent-sweep、agentexport）之后，拾光有两组问题：

**一组是缺口。** 同类都有、我们没有，缺了会在功能对比上直接吃亏：token/成本统计、跨会话全文搜索、三平台打包、CI。

**一组是机会。** 同类一个都没有：会话对比、失败聚类、脱敏自审、可核对的离线证据、跨会话项目视图、子代理产出归因、复盘导出。

还有一个定位问题："完全离线"不是差异点——hindcast 说 "Local-only, by construction"，zoetrope 说 "Zero network, provably"，CCHV 说 "100% offline"。同类产品全都在说这一句。真正的空白是**查看器侧的脱敏**：agent-sweep 是改写原始文件的 CLI（所以需要 `.bak`、`--allow-production`、`undo`），agentexport 直接上传且完全不做清洗。在展示与导出层打码、原文一字节不动，这条路目前没有人走。

三个已确认的前提：

1. **两条腿**：先补齐基本盘，再做差异化。
2. **provider 只留位不实现**：本次不支持 Claude Code，但保证以后加它改的是新增文件而不是既有文件。
3. **差异化主轴是"可安全分享"**：脱敏自审面板、离线自检页、复盘导出。

## 二、架构骨架

### 三个新接缝

整套方案只往架构里加三个接缝，其余都是在现有层里填内容。

| 接缝 | 位置 | 形状 | 理由 |
| --- | --- | --- | --- |
| 用量采集 | `normalizeRecords` | 新增 `noteUsage` 回调 | 已有同形状的 `noteNoise`（`src/main/parsers/normalize.ts:1235`）。用量记录本来走噪音分支，丢弃前把数字捞走即可 |
| provider 位 | `SessionSummary` + `scanner/paths.ts` | 一个字段 + 一层目录分组 | 不引入接口、不做注册表 |
| 脱敏遥测 | `redactText` / `redactDeep` | 可选 sink 参数 | 现在是纯函数，几十处调用。改返回值要动全部调用点，加可选 sink 只动需要报告的那处 |

### 存储与契约

`LocalStore` 现在是三个 JSON 文件（`src/main/storage/store.ts:18`），搜索索引成为第四个。旧索引缺字段照 `withDefaults`（`store.ts:192`）补默认值，不逼用户重扫。IPC 从 19 个方法加到 22 个：搜索、脱敏自审、离线自检各一个。

### 写死的非目标

- **不做实时跟随。** 终端本身在显示流，再抄一份只是多一个会不同步的副本。
- **不做模型总结。** 所有数字必须确定性可复现。
- **不改写原始文件。** 这是与 agent-sweep 那类工具的根本分歧。
- **不为体积重写成 Tauri。** 111 MB 认了，改为审计 asar 与打包进来的 locale，目标砍 20—30%。

## 三、补齐这条腿

### 3.1 用量聚合

用量数字现在被整条丢掉——`token_count`、`token_usage`、`usage`、`rate_limits` 都在 `NOISE_RECORD_TYPES` 里（`src/shared/constants.ts:298`）。记录继续丢弃，丢弃前把数字捞出来。

**必须先解决一个陷阱：这些数字是累计值，不是增量。** `fixtures/sample-agent-harness.jsonl` 第 6、10、22 行的 `total_token_usage.total_tokens` 依次是 **4390 → 5100 → 9760**，单调递增。直接求和得 19250，真值 9760，接近翻倍，而且会话越长错得越多。

判据不看字段名（`total_token_usage` 与 `last_token_usage` 在不同 Codex 版本里语义不同），而看**数列形状**：

> 整条序列单调不减 ⇒ 累计值，取最后一条。
> 出现下降 ⇒ 增量值，求和。

这条规则自带纠错：猜错字段语义会算错，看数列形状不会。序列中途归零（换会话、上下文压缩）会被判为增量并求和，这正是想要的结果。

```ts
export type UsageBasis = 'cumulative' | 'delta'

export interface UsageSummary {
  inputTokens: number
  outputTokens: number
  cachedInputTokens: number | null   // 有的版本没有这个字段
  totalTokens: number
  /** 记下用了哪条规则，便于排错和界面提示 */
  basis: UsageBasis
  /** 按模型拆分；日志里没写模型名时只有一条 'unknown' */
  byModel: Array<{ model: string; totalTokens: number }>
  /** task_started 里的 model_context_window，用来算上下文占用率 */
  contextWindow: number | null
}
```

`SessionSummary.usage` 可空。**没有就是"日志未记录用量"，绝不显示 0**——这与现有的"结果未记录"而不是判失败是同一条原则：谎报比不报更糟。

**不发货价格表。** 单价在设置里由用户自己填（每百万 token 的输入/输出价），默认为空则只显示 token 数不显示金额。写死的价格表会过期，过期的价格表比没有价格表更糟。

### 3.2 跨会话搜索

现在 19 个 IPC 方法里没有搜索，`library.ts` 只在已加载的摘要上过滤。hindcast 的做法是调 ripgrep——这条路对我们**结构性不可用**：`tests/security/offline.test.ts` 禁止 `child_process`、`spawn(`、`execFile(`。所以只能自己建索引。

两层设计：

**第一层 · 倒排索引。** 在现有扫描过程里建。扫描时事件已经在内存里、算完摘要就丢掉，顺手建索引是零额外 I/O。存为 `LocalStore` 的第四个文件，生命周期与 `session-index.json` 完全一致（增量、按文件大小与修改时间失效、取消扫描时不删）。

**第二层 · 命中定位。** 查询先在倒排表里求交集得到候选会话，再走现有 `sessionGet` 逐个加载定位到具体事件——内存里最多同时保留 3 个完整会话，这个约束不变。

**分词。** ASCII 侧保留标识符与错误码的完整形态（`ENOENT`、`TS2345`、`node_modules` 必须能整词搜到，不能被下划线和数字切碎）；中文走 bigram。短语搜索在第二层做精确匹配，正则降级为可取消的全量扫描，复用现有的取消机制。

**索引无条件建在打码后的文本上。** 这是本方案里唯一一处主动接受功能损失：索引文件会落盘，如果建在原文上，它就成了一个今天不存在的泄露面——现在的 `session-index.json` 只有标题和路径。代价是密钥搜不到；这个代价可以接受，甚至是想要的。相应地，新文件必须列进 `privacyNotice` 的输出，并被 `sessionsClear` 清掉。

**体积预算 ~30 MB**（现有索引 2.6 MB，674 个会话）。超预算时按词频从低价值词开始丢弃，并在设置里提供关闭开关。

### 3.3 resume 命令

设置里一个可编辑模板，默认 `cd -- {dir} && codex resume {threadId}`，占位符从会话里填。**只复制到剪贴板，绝不执行**——执行就要 `child_process`，那是红线。

### 3.4 CI 与三平台

两个 workflow，同时补掉"没有 CI"和一半的"只在 Windows 验证过"：

- `verify.yml`：windows / macos / ubuntu-latest × Node 20，`--frozen-lockfile` + `pnpm verify`，设为必需检查。mac/Linux 的路径代码写在 `paths.ts` 里但从没在那两个平台上跑过，这一步让它们真的执行。
- `release.yml`：打 tag 触发，三平台 `electron-builder`，`SHA256SUMS.txt` 上传到 Release。`publish: null` 保持不动，不引入自动更新渠道。

CI 里额外做一件为第四节服务的事：把完整依赖树打进构建日志并作为构建产物保存，供离线自检页展示。

## 四、差异化这条腿：可安全分享

一句话立场：**你分享出去之前，可以自己核对一遍打了什么、漏了什么、以及这个应用凭什么说它不联网。**

现在的打码是"相信我"，这一节把它变成"你自己看"。

### 4.1 遥测接缝

`redactText` / `redactDeep` 现在是纯函数、几十处调用点。改返回值要动全部调用点；加一个**可选 sink 参数**只动需要出报告的那一处（`library.ts` 的打码出口和导出路径）。这与 `normalizeRecords` 里 `noteNoise` / `noteUsage` 是同一种写法。

```ts
export interface RedactionSink {
  hit(hit: RedactionHit): void
  kept(keyName: string, reason: KeptReason): void
}

export function redactText(input: string, sink?: RedactionSink): string
export function redactDeep(value: unknown, keyHint?: string, depth?: number, sink?: RedactionSink): unknown
```

不传 sink 时行为与今天完全一致，现有测试一行不用改。

### 4.2 脱敏自审面板

三块内容，分别回答三个问题。

**一、打了什么。** 按规则分组的命中计数，每条给出打码后的上下文与可点击的事件定位。

```ts
export interface RedactionHit {
  /** 'known-secret:sk-' | 'cookie-line' | 'auth-scheme' | 'cli-flag' | 'key-value' | 'sensitive-key' */
  rule: string
  keyName: string | null
  eventId: string | null
  /** 打码后的上下文片段 */
  maskedContext: string
}
```

**这里有一条不可违背的约束：命中报告绝不携带原值。** 一个为打码而生的审计面板如果把它找到的密钥回显出来，它自己就是泄露口。所以 `maskedContext` 存的是替换后的文本，且审计结果不进任何导出产物（只有汇总计数进）。

**二、可能漏了什么。** 一切规则都没匹配上、但看起来像密钥的字符串。

这是整个方案里技术风险最高的一处，必须先把风险说清楚：高熵检测的天然结局是**淹没在噪音里**。会话日志里高熵长串到处都是——git SHA、`sha512-` 锁文件哈希、base64 图片、UUID、长路径、minified 代码片段、CJK 文本（按字节算熵很高）。一个"检出 400 条可疑"的面板等于没有面板。

所以这里**不做告警，只做排序**：

> 按可疑度降序，固定只显示前 20 条，每条可点击定位。

这个决定绕开了校准难题。阈值型告警的可用性完全取决于精确率，而定长排序列表在任何精确率下都是可用的——用户从最可疑的那条开始看，看到不像了就停。排序信号是确定性的：字符类混合度、Shannon 熵、长度、是否落在已知排除形态里（排除只降权、不删除，避免真密钥恰好长得像 UUID 时被彻底藏起来）。

与命中报告相反，**残留条目可以显示原文**——它本来就没被打码，已经明明白白在时间线上；藏起来才是自欺。

**三、什么被判为不是密钥。** 这是同类工具都没有的反向报告：`author`（含 auth）、`keyboard`、`input_tokens` / `total_tokens` 这类用量字段、源码里的 `password: str = Field(...)`（`str` 是类型名）。每条给出键名、次数和排除理由。

这一块的价值在于它是**可反驳的**：用户看到"`api_key_name` 因为命中 xx 排除规则而未打码"，可以立刻判断这是对的还是错的。今天这些排除规则藏在 `patterns.ts` 里，没人看得见。

**面板入口放在导出对话框旁边**，位置本身就是这个功能的说明书：分享之前先看一眼。

### 4.3 离线自检页

README 里那些安全措施现在只是文字。这一页把它们变成运行时可核对的证据。

六项内容：

| 项 | 来源 | 现状 |
| --- | --- | --- |
| 应用自身发起而被拦截的请求数（应为 0）与清单 | `applySessionSecurity` 里加计数器 | 现在只 `console.warn`（`src/main/security.ts:65`），没人看得见 |
| 当前生效的 CSP（两份策略并列，不合并） | meta 标签那份从 DOM 真实读取；响应头那份来自实际装上去的头 | 已有，未展示 |
| preload 暴露的方法清单 | 运行时枚举 `window.gleam` 的键 | 已有，未展示 |
| TLS 验证器状态 | `setCertificateVerifyProc` 恒返回 -3 | 已有，未展示 |
| 构建期校验结果（测试数、git sha、时间） | CI 产出的 JSON，打包进应用 | 新增 |
| 完整依赖树 | CI 产物 | 新增 |

第一项的计数必须把**应用自身发起的请求**和**用户按"你自己试"主动触发的请求**分开计，否则演示一次拦截就把"应为 0"这个指标弄脏了，指标一脏就再也没人看它。

第 2 项在实现时量出一件原本没预料到的事：这个应用有**两份** CSP，而且它们不一样。
`electron.vite.config.ts` 注入进 `index.html` 的那份有 13 条指令，`security.ts` 装在每个响应上的那份只有 10 条——
后者少了 `media-src` / `worker-src` / `manifest-src` 三条。两份都真实生效，生效的层次还不同：
一个是文档解析时就位、管这个窗口里的一切加载，一个是每个响应上带的头。开发模式下两份的命运也不同——
注入 meta 的是个 `apply: 'build'` 的构建插件，开发服务器下压根不插；装响应头的那段被 `isDev` 判断挡着。

所以自检页**并列展示两份、不合并**，并在指令数不同时解释多出来的是哪三条。合成一行显示会把这件事抹掉，
而"抹掉一个差异"和"撒谎"之间没有实质区别。meta 那份从 `document.querySelector` 读 DOM 里的真实对象，
不从构建配置抄一份常量过来；响应头那份来自主进程记下的实际装上去的值，开发模式下就是空的，那一格就照实说空。

第 3 项特别值得单列：它枚举的是**真实对象**而不是文档里抄的一份清单，所以文档写错了它也不会跟着错。

**还有一个"你自己试"按钮。** 页面上一个输入框，用户填任意 URL，点一下，应用尝试加载它并把拦截结果显示出来。

这里有个约束要绕：渲染进程不能出现 `fetch(`、`XMLHttpRequest`、`new WebSocket`——安全测试扫源码。用 DOM 创建 `Image` 并设 `src`、监听 `onerror` 即可，不触碰任何被禁的标识符，而 CSP 的 `img-src 'self' data:` 正好会拦住它，演示的就是这个拦截。

URL 由**用户输入**而不是写在源码里，有两个好处：源码里不出现任何外部地址（安全测试无需开例外），以及"目标由你选"比"我们预设了一个"更有说服力。

拿不到构建期证据（第 5、6 项）时明确说这次读不到，不假装有。判据是文件读没读到，不是当前跑在什么模式下——
开发机上跑过 `pnpm evidence` 之后它就该照实显示。

### 4.4 复盘导出

`reportModel.ts` 上的第四个格式化器，`ExportFormat` 加一个 `'retro'` 值，输出 Markdown。前三种导出回答"发生了什么"，这一种回答"结论是什么"：

1. 一句话结论（成功 / 失败 / 部分完成，确定性规则判定）
2. **净改动**而不是每一步改动
3. 走过的弯路：失败后重试成功的命令序列
4. 测试由红转绿的转折点
5. 用量（来自 3.1）
6. 脱敏审计摘要：本次导出打码 N 处、可疑残留 M 条

**净改动的算法与它的局限：** 同一个文件被改 5 次时，取第一次的 `before` 与最后一次的 `after`。只有 diff 没有前后内容时，退化为按顺序列出各次 diff 并明确标注"未合成净改动"——不猜、不假装合成成功。

第 6 项让脱敏这件事出现在产物本身里，而不只是应用界面里。这是"可安全分享"这条主轴的收口。

## 五、错误处理

沿用项目现有的一条原则：**没有数据就说没有，不要拿 0 冒充。**（现存的"结果未记录"而不是判失败就是这条。）

| 情况 | 行为 |
| --- | --- |
| 日志里没有用量记录 | 显示"日志未记录用量"，不显示 0 |
| 用量数字是字符串 / 缺字段 | 走 `validators.ts` 的容错转换，转不了就当缺失 |
| 搜索索引缺失或损坏 | 降级为只搜标题，明确提示，不阻塞界面 |
| 索引版本不匹配 | 照 `withDefaults`（`store.ts:192`）补默认值，不逼用户重扫 |
| 审计 sink 抛异常 | 吞掉并记为"审计不可用"。导出是主功能，审计是附加信息，绝不能因为附加信息失败而导不出 |
| 残留片段太多 | 排名表按不同片段数封顶（2000 条，超了剪到 1000），撞过上限就说"片段太多，只拿最可疑的一批参与了排名"，并给出精确的表内条数。**不用挂钟超时**：挂钟让输出随机器快慢而变，和"排序稳定且可复现"直接冲突。上限管住内存，剪枝的正确性论证管住结果——剪掉的那些永远排在留下的 1000 条之后，1000 > 20，所以面板上那 20 条是**精确的**前 20 条 |
| 自检页拿不到构建期证据 | 照实说这次读不到，不假装有。判据是**文件在不在、能不能解析**，不是"当前是不是开发模式"——开发机上跑过一次 `pnpm evidence`，`build/generated/` 里就真有东西了，那时它就该照实显示。反过来"开发模式"也不等于"一定没有"，把话说死会让一个真实存在的证据被隐藏起来 |
| 净改动无法合成 | 标注"未合成净改动"并列出各次 diff |

## 六、测试与验收

新增测试挂在现有目录结构下（`tests/parsers/`、`tests/redaction/`、`tests/exporters/`、`tests/security/`）。

**用量**：累计序列、增量序列、单条记录、非单调（中途归零）序列、数字为字符串、字段缺失、模型名缺失。断言 `fixtures/sample-agent-harness.jsonl` 得出 **9760** 而不是 19250。

**搜索**：分词（中英混排、`ENOENT` / `TS2345` / `node_modules` 整词可搜）、倒排交集、索引失效（文件改动 / 删除 / 取消扫描）。**关键断言：往 fixture 里放一个 `sk-` 形态的伪造密钥，断言它在索引里搜不到**——这是 3.2 那个设计决定的可执行形式。

**脱敏审计**：命中报告不含原值（**关键断言**）、被排除的键给出理由、残留排序稳定且可复现、命中明细不进导出产物（只有汇总计数进）。

**自检**：自身拦截计数与用户触发的拦截计数分开累加、preload 方法清单与 `api.ts` 的实际导出一致（清单错了测试就红）。

**复盘导出**：净改动合成、无法合成时的标注、沿用现有"无外链"断言。

**安全测试自身扩展**：新增文件不引入任何被禁 API；渲染进程侧的"你自己试"按钮不出现 `fetch(` / `XMLHttpRequest` / `new WebSocket`。
